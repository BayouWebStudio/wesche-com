Spark-Bench

57 scenarios · 10 domains · partial-credit grading · Pass@1/Pass@K trial statistics · visual artifact generation

Spark-Bench is a mixed-capability LLM benchmark built specifically for the NVIDIA DGX Spark (GB10 Grace-Blackwell) platform. It evaluates models across 57 scenarios in 10 domains — tool use, instruction following, structured output, long context retrieval, safety, robustness, multi-step tool chains, restraint/refusal detection, autonomous planning, and visual artifact generation.

Unlike saturated leaderboards where every decent model clusters at 88–97, Spark-Bench is designed to discriminate. Grading is deterministic (no LLM-judge): unit tests, JSON-schema validation, exact tool-argument matching, and needle retrieval. Models receive partial credit — hitting 3/5 constraints scores 0.60, not 0.00.

Every scenario runs K=2 times. We report Pass@1 (passes on at least one trial), Pass@K (passes on ALL trials), and the Reliability Gap between them — so you know not just whether a model can do it, but whether it consistently can.

Visual scenarios ask models to generate self-contained HTML5 canvas animations (no external libraries). Every animation on this page is raw model output, unedited.

Methodology

Most LLM leaderboards saturate — every decent model clusters at 88–97 and the ranking stops meaning anything. Spark-Bench is built to discriminate and to be verifiable:

  • 10 domains — tool use, instruction following, structured output, long context, safety, robustness, multi-step tool chains, restraint/refusal, autonomous planning, visual generation.
  • 57 scenarios — including 3 multi-step tool chains, 4 restraint/refusal (over-refusal detection), 2 autonomous planning, 3 hard instruction following, and 3 visual artifact generation scenarios.
  • Partial-credit grading — a model hitting 3/5 constraints scores 0.60, not 0.00. No binary pass/fail.
  • Deterministic grading — unit tests, JSON-schema validation, exact tool-argument matching, needle retrieval. No LLM-judge.
  • Multi-turn tool calls — graders check the full tool call sequence, not just the first response. Models that call calculator before send_email get partial credit.
  • Trial statistics — Pass@1 (≥50% on at least 1 repeat), Pass@K (≥50% on ALL repeats), Reliability Gap, Score StdDev, Scenario StdDev.

TrueScore formula

TrueScore = 0.40·Quality + 0.25·Calibration + 0.15·Reliability + 0.05·Efficiency + 0.15·Responsiveness

Quality = task correctness across capability domains. Calibration = safety + robustness (knowing when to refuse/abstain). Reliability = consistency across repeated trials. Efficiency = useful-token ratio (anti-overthink). Responsiveness = latency-derived score.

The hardware

  • 4× NVIDIA DGX Spark (GB10 Grace-Blackwell, 128 GB unified memory each).
  • Local models: served via llama.cpp (Q4_K_M quantization) or vLLM (NVFP4). One model per Spark at a time.
  • API models: served via OpenRouter for comparison against local deployment.
  • Pure stdlib Python — no pip dependencies. Any OpenAI-compatible /v1/chat/completions endpoint works.
