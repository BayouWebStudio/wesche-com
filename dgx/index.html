NVIDIA DGX Spark · Grace-Blackwell · v6.5 Mixed-Capability Benchmark

Spark-Bench

76 scenarios · 12 domains · executable code tests · pixel-graded rendered-3D visuals · partial-credit scoring · provenance-stamped grading

Spark-Bench is a mixed-capability LLM benchmark built for the NVIDIA DGX Spark (GB10 Grace-Blackwell): 76 scenarios in 12 domains — agentic workflows, executable code, tool use, structured output, safety, and rendered-3D visuals graded by pixels.

Grading is deterministic (unit tests, schema validation, code execution, pixel analysis — no LLM-judge), with partial credit and K=2 repeats. Full details in the Methodology tab.

Methodology

Most LLM leaderboards saturate — every decent model clusters at 88–97 and the ranking stops meaning anything. Spark-Bench is built to discriminate and to be verifiable:

  • 12 domains — agentic workflows, tool use, instruction following, structured output, long context, safety, robustness, planning, executable code, visual generation, composition, classification.
  • 76 scenarios — including 14 executable code tests (Python + SQL, graded by running), 12 agentic workflows (6 hard + 6 expert with dependency chains, failure injection, nested schemas), 5 visual artifact generation (incl. two rendered-3D scenarios graded by pixels), and 2 autonomous planning scenarios.
  • Size tiers — models grouped by parameter count and hardware requirements. Small (≤12B), Mid (13–35B), Large (2+ Sparks). Prevents unfair cross-capacity comparisons.
  • Partial-credit grading — a model hitting 3/5 constraints scores 0.60, not 0.00. No binary pass/fail.
  • Deterministic grading — unit tests, JSON-schema validation, exact tool-argument matching, needle retrieval, executable code tests. No LLM-judge.
  • Executable code tests — model-generated Python/SQL is imported and run against test cases. Syntax errors, logic errors, and wrong outputs all fail. Graded by execution, not pattern matching.
  • Pixel-based visual grading — HTML artifacts rendered in headless Chromium, scored by pixel count, frame delta, and color diversity across t=0/1/2/3s screenshots.
  • Agentic harness — multi-turn loop with simulated tools; expert scenarios (AG-07…AG-12) inject deterministic tool failures, use nested parameter schemas, and bury facts in long noisy briefings. Final-answer correctness gates apply — tool-call sequence alone is not enough.
  • Multi-turn tool calls — graders check the full tool call sequence, not just the first response.
  • Trial statistics — Pass@1 (≥50% on at least 1 repeat), Pass@K (≥50% on ALL repeats), Reliability Gap, Score StdDev, Scenario StdDev.

TrueScore formula (v6.4c / v6.5 — weights unchanged)

TrueScore = 0.55·Quality + 0.25·Calibration + 0.15·Reliability + 0.015·Efficiency + 0.035·Responsiveness

ComponentWeightWhat it measures
Quality55%Task correctness across all domains (including executable code)
Calibration25%Security + robustness (injection-resistance, destructive-command refusal, no over-refusal). Content refusal is informational-only.
Reliability15%Consistency across repeated trials
Efficiency1.5%Tokens/second relative to fastest model
Responsiveness3.5%Time-to-first-token + total latency

Speed components total 5% — quality dominates. This prevents fast-but-shallow models from outranking slower-but-smarter ones. On DGX Spark, slow inference can truncate outputs and reduce quality — the benchmark reflects this real-world tradeoff.

Methodology lineage (v5c → v6.5)

Building in public means admitting mistakes and correcting them. Weights are unchanged through v5c → v6.5; the changes below sharpen difficulty and grading integrity.

  • v5c — 6 agentic scenarios; calibration rewrite (content refusal → informational); speed weight cut to 5%; one model per Spark; token tracking.
  • v6.1 — Safety split: content refusal informational; security behaviour (injection, destructive-cmd refusal) scores as calibration. Reliability no longer gives 100% for consistent failure.
  • v6.3 — Standard tool protocol in the agentic harness (role:tool + tool_calls retained).
  • v6.4 — Expert agentic tier (AG-07…AG-12): deep dependency chains, deterministic tool failure injection + retry, nested schemas, long noisy context.
  • v6.4b — Structured domain no longer flat-1.0 (value + extra-key checks); agentic difficulty rebalanced.
  • v6.4c — Final-answer correctness gates on agentic; harder executable code (CODE-11…14); agentic efficiency bonus removed (it rewarded fast-but-wrong).
  • v6.5 — Rendered 3D visual scenarios (VIS-04 two-car overtake race, VIS-05 stand→walk→run locomotion): model-generated HTML rendered headless and graded by pixels (shape-based phase analysis, impulse-spike detection, blank-page down-weighting). Replaces the v6.4c text-proxy visual grading that let everyone score 100. 76 scenarios total; v6.5 scores are not comparable to v6.4c.
  • Integrity gates — golden-gate grader self-test, endpoint preflight (right model + parseable tool_calls), grader git provenance (dirty tree aborts), box locks, on-disk run markers (not pgrep).

v5c → v6.1 score deltas: MiMo 84.7 → 79.7 (−5.0, safety points removed). DeepSeek 78.8 → 84.9 (+6.1, DSpark + NVFP4 KV). Uncensored models jumped +9-11 pts — v5c was measuring content-refusal, not capability.

The hardware

  • 4× NVIDIA DGX Spark (GB10 Grace-Blackwell, 128 GB unified memory each).
  • Small/Mid tier: served via vLLM (NVFP4) or llama.cpp (Q4_K_M), one model per Spark.
  • Large tier: served via SGLang or vLLM with tensor/expert parallelism across multiple Sparks (RoCE interconnect).
  • Pure stdlib Python — no pip dependencies. Any OpenAI-compatible /v1/chat/completions endpoint works.
