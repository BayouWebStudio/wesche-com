NVIDIA DGX Spark · Grace-Blackwell · v5c Mixed-Capability Benchmark

Spark-Bench

64 scenarios · 11 domains · size-tiered leaderboards · executable code tests · pixel-graded visual artifacts · partial-credit scoring

Spark-Bench is a mixed-capability LLM benchmark built specifically for the NVIDIA DGX Spark (GB10 Grace-Blackwell) platform. It evaluates models across 64 scenarios in 11 domains — tool use, instruction following, structured output, long context retrieval, safety, robustness, multi-step tool chains, restraint/refusal detection, autonomous planning, executable code generation, and visual artifact generation.

Models are grouped into size tiers so small models compete against peers of similar capacity. A 2B dense model isn't compared head-to-head with a 35B MoE — instead, each tier has its own leaderboard.

Grading is deterministic (no LLM-judge): unit tests, JSON-schema validation, exact tool-argument matching, needle retrieval, executable code tests (model-generated Python/SQL is imported and run), and pixel-based visual artifact analysis. Models receive partial credit — hitting 3/5 constraints scores 0.60, not 0.00.

Every scenario runs K=2 times. We report Pass@1 (passes on at least one trial), Pass@K (passes on ALL trials), and the Reliability Gap between them.

Methodology

Most LLM leaderboards saturate — every decent model clusters at 88–97 and the ranking stops meaning anything. Spark-Bench is built to discriminate and to be verifiable:

  • 11 domains — tool use, instruction following, structured output, long context, safety, robustness, multi-step tool chains, restraint/refusal, autonomous planning, executable code, visual generation.
  • 64 scenarios — including 10 executable code tests (Python + SQL, graded by running), 3 visual artifact generation, 4 restraint/refusal (over-refusal detection), and 2 autonomous planning scenarios.
  • Size tiers — models grouped by parameter count and hardware requirements. Small (≤12B), Mid (13–35B), Large (2+ Sparks). Prevents unfair cross-capacity comparisons.
  • Partial-credit grading — a model hitting 3/5 constraints scores 0.60, not 0.00. No binary pass/fail.
  • Deterministic grading — unit tests, JSON-schema validation, exact tool-argument matching, needle retrieval, executable code tests. No LLM-judge.
  • Executable code tests — model-generated Python/SQL is imported and run against test cases. Syntax errors, logic errors, and wrong outputs all fail. Graded by execution, not pattern matching.
  • Pixel-based visual grading — HTML artifacts rendered in headless Chromium, scored by pixel count, frame delta, and color diversity across t=0/1/2/3s screenshots.
  • Multi-turn tool calls — graders check the full tool call sequence, not just the first response.
  • Trial statistics — Pass@1 (≥50% on at least 1 repeat), Pass@K (≥50% on ALL repeats), Reliability Gap, Score StdDev, Scenario StdDev.

TrueScore formula (v5c)

TrueScore = 0.55·Quality + 0.25·Calibration + 0.15·Reliability + 0.015·Efficiency + 0.035·Responsiveness

ComponentWeightWhat it measures
Quality55%Task correctness across all domains (including executable code)
Calibration25%Safety + robustness (appropriate behavior, no over-refusal)
Reliability15%Consistency across repeated trials
Efficiency1.5%Tokens/second relative to fastest model
Responsiveness3.5%Time-to-first-token + total latency

Speed components total 5% — quality dominates. This prevents fast-but-shallow models from outranking slower-but-smarter ones. On DGX Spark, slow inference can truncate outputs and reduce quality — the benchmark reflects this real-world tradeoff.

The hardware

  • 4× NVIDIA DGX Spark (GB10 Grace-Blackwell, 128 GB unified memory each).
  • Small/Mid tier: served via llama.cpp (Q4_K_M quantization), one model per Spark.
  • Large tier: served via SGLang or vLLM with tensor/expert parallelism across multiple Sparks (RoCE interconnect).
  • API models: served via OpenRouter for comparison against local deployment.
  • Pure stdlib Python — no pip dependencies. Any OpenAI-compatible /v1/chat/completions endpoint works.
