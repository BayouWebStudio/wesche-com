Asteroids: Two Local Models, One Memorized Game.

Read before comparing

The setup, the caveats, the limits.

Prompt, verbatim: "Build a playable Asteroids game as a single self-contained HTML file (inline CSS/JS, no external libraries, assets or network). Capture the 1979 Atari feel: rotate/thrust, shoot and split asteroids, screen wrap, lives, score, waves, game over and restart. Add any polish you think makes it feel great. Output only the HTML file in one code block."

Both ran under Hermes with /reasoning ultra, uncapped output, from the same fresh session state. DeepSeek finished in 59 minutes, GLM in 78. GLM spent roughly a third of its run on a headless-Chrome smoke test with mutator hooks before writing the clean file.

Recording method: same simulated keyboard schedule on both. Each game seeds its own asteroid field, so ship paths differ even with identical inputs. Both scored 1000+ and lost a life inside 40 seconds.

What this proves: not much about the models. Asteroids is in every training set. The follow-up lighthouse study used an underspecified Three.js brief for exactly this reason.
