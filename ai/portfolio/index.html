01 / Security tools

What is already public.

The scanner reads what anyone can see. It does not talk to a chatbot.

GitHub

Checkup scanner

Python 3.9 · public DNS, HTTPS, certificate logs · passive unless --authorized

Give it a domain. It grades five areas red, yellow, or green and writes a plain fix list: email spoofing (SPF, DKIM, DMARC), the website (HTTPS, HSTS, content-security headers), exposed software and hostnames, known breaches, and whether a chat widget is on the site. With --browser it loads the page so it can see widgets added by scripts. It detects the widget. It does not talk to it. Active checks, such as looking for an exposed .env, run only with --authorized, and the report records who gave permission. What it shows: the public exposure of a small-business site, not that a chatbot is safe.

github.com/Weschera/checkup-scanner (opens in a new tab)↗

02 / AI red-teaming and model research

Compression, refusals, and the runs that failed.

Quantization, a publisher's abliteration claim, and experiments that keep the miss.

GitHub

The Qwen quantization ladder

One DGX Spark (GB10, 128 GB) · vLLM and llama.cpp · NVFP4, FP8, GGUF, bf16 · native MTP

The same Qwen3.8-27B model, served at four compression levels, with speculative decoding where the engine can drive the native draft head. A script checks that the process you launched is the quant you think it is. What it shows: a smaller file is a different deployment. The write-up does not claim quantization was the only thing that changed.

github.com/Weschera/Qwen3.8-27B-DGX-Spark-Quant-Ladder (opens in a new tab)↗
GitHub

Uncensored Qwen, publisher's abliteration

2× DGX Spark · vLLM tensor-parallel 2 · FP8 · MTP · 128K context

A serving recipe for a Qwen3.8-Flash-Next checkpoint. The publisher describes it as refusal-direction abliteration: the refusal behavior was edited out of the weights. This repo measures whether that file serves. It includes no safety test, and it says so. What it shows: "uncensored" is the publisher's claim, not a result from this repo, and not evidence the model is safe in front of customers.

github.com/Weschera/qwen-flash-next-uncensored-fp8-2x-dgx-spark (opens in a new tab)↗
GitHub

When a serving recipe changes the score

2× DGX Spark · GLM-5.3-Flash · EXL3

Two pinned revisions of a serving recipe, with the full transcripts. A chat-template change is part of the difference, and the pack also records a different grader revision. The measured score moved. What it shows: a benchmark number belongs to a recipe, not to a model name alone.

github.com/Weschera/GLM-5.3-Flash-EXL3-recipe-regression-2026-09 (opens in a new tab)↗
Lab

Melon jelly

DeepSeek V4 Flash · vLLM TP2 · two DGX Sparks · Qwen3.8-27B 4-bit · TensorFold · Mac Studio M4 Max

One hard WebGPU prompt, two local engines. Neither produced a jelly you can grab. The broken originals are published next to a one-edit repair. What it shows: a local model can return a file that still does not run, and the failure stays in the record.

Qwen Flash-Next FP8 · 2× DGX Spark · Qwen 27B MLX 8-bit · Mac Studio

Two models produced a floating island. A third, AEON, did not produce a working file on the attempts the page counts as model failures. Timeouts and output caps are listed separately, so they are not counted as the model failing. What it shows: a missing result stays on the page.

03 / Local AI infrastructure

Models on hardware you control.

Spark-bench, and the Mac recipes. The numbers stay in the repos.

GitHub

Spark-bench

NVIDIA DGX Spark (GB10) · tool use, multi-step work, and code · transcripts in the repo

A benchmark for models served on DGX Spark. The method and the run transcripts are in the repo. Published comparisons also include a Mac Studio and some hosted models. The README calls it an operator bench for this hardware, not a ranking of every model. What it shows: a score you can tie back to the recipe that produced it.

github.com/Weschera/spark-bench (opens in a new tab)↗
GitHub · Mac

Qwen 27B on a Mac Studio

Mac Studio M4 Max, 128 GB · oMLX · native MTP · same-day rerun on the same machine

A measured recipe for Qwen 3.8 27B on a Mac Studio, with the raw benchmark JSON in the repo and a same-day comparison against earlier oMLX setups. What it shows: the model running on hardware you control, with the measurement file attached. That is one way to keep client files off a public chatbot.

Qwen Flash Next on Apple Silicon

A deployment guide for Qwen3.8 Flash Next on a Mac, written so the setup can be checked rather than taken from a screenshot. What it shows: the steps for that serving path, in the repo.

GitHub · Mac

Native MTP vs DFlash on Mac

Mac Studio M4 Max, 128 GB · MLX · Qwen3.8-27B · 8-bit and 4-bit

Two speedup methods for the same model. The faster MTP path corrupted one of two replies when it served them at once, and the repo includes a 4-bit versus 8-bit follow-up. What it shows: a higher token rate is not, by itself, a correct answer.

DeepSeek vision on a Mac Studio

Mac Studio M4 Max, 128 GB · DwarfStar (C and Metal) · DSpark draft · DeepSeek V4 Flash Vision-Exp

A native Mac deployment of a vision model, with the pagoda artifact and the repair record. The repo separates how much context was configured from how the model behaved when that context was filled, and it includes a comparison with DGX Spark runs. What it shows: a local vision model with the repair written down.
