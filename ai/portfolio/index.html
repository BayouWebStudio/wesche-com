01 / Security tools

What is already public.

The scanner reads what anyone can see. It does not talk to a chatbot.

GitHub

Checkup scanner

An outside-in check of a business domain: email spoofing, the website, known breaches, and whether a chat widget is present. It grades each area red, yellow, or green and writes a plain fix list. The first AI risk is often what is already exposed.

02 / AI red-teaming and model research

Compression, refusals, and the runs that failed.

Quantization, a publisher's abliteration claim, and experiments that keep the miss.

GitHub

The Qwen quantization ladder

The same Qwen model, served at several compression levels on one DGX Spark, with a script that checks you launched the file you think you launched. A smaller file is faster. It is not the same deployment.

github.com/Weschera/Qwen3.8-27B-DGX-Spark-Quant-Ladder (opens in a new tab)↗
GitHub

Uncensored Qwen, publisher's abliteration

A serving recipe for a Qwen model whose publisher says the refusal behavior was removed, a change called abliteration. The repo measures whether the model serves. It includes no safety test, and it says so.

github.com/Weschera/qwen-flash-next-uncensored-fp8-2x-dgx-spark (opens in a new tab)↗
GitHub

When a serving recipe changes the score

Two pinned versions of a GLM serving recipe, with the full transcripts. A template change moved the measured score. A benchmark number is only as trustworthy as the recipe that produced it.

github.com/Weschera/GLM-5.3-Flash-EXL3-recipe-regression-2026-09 (opens in a new tab)↗
Lab

Melon jelly

A hard, specific prompt sent to a local DeepSeek and a local Qwen. Neither produced a working result. The broken originals are published next to a one-edit repair, so the miss is not edited out.

wesche.com/lab/experiments/melon-jelly ↗
Lab

A world built. A failure kept.

Two models produced a floating island. A third model arm did not produce a working file, and that miss stays on the page. The notes separate a harness failure from a model failure, so a broken run is not counted twice.

wesche.com/lab/experiments/voxel-island ↗
GitHub

Reproduce a visual comparison

A small harness that keeps a model's original answer, the generated page, and any repair in separate files. A comparison is only useful if someone else can see what the model actually returned.

github.com/Weschera/dual-model-visual-harness (opens in a new tab)↗
03 / Local AI infrastructure

Models on hardware you control.

Spark-bench, and the Mac recipes. The numbers stay in the repos.

GitHub

Spark-bench

A public benchmark for models running on local NVIDIA DGX Spark hardware: tool use, multi-step work, and code, with the transcripts in the repo. It checks a serving recipe. It is not a ranking of every model on the internet.

github.com/Weschera/spark-bench (opens in a new tab)↗
GitHub · Mac

Qwen 27B on a Mac Studio

A measured recipe for Qwen 3.8 27B on a Mac Studio, with the raw benchmark file in the repo and a same-day comparison against another Mac setup. A model on hardware you control is one way to keep client files off a public chatbot.

github.com/Weschera/Qwen3.8-27B-oMLX-MTP-Mac (opens in a new tab)↗
GitHub · Mac

Qwen Flash Next on Apple Silicon

A checked deployment guide for Qwen3.8 Flash Next on Apple Silicon. The steps are written down so someone else can see what was actually run.

github.com/Weschera/qwen38-flash-next-omlx-mac (opens in a new tab)↗
GitHub · Mac

Native MTP vs DFlash on Mac

A Mac Studio study of two speedup methods for Qwen3.8-27B, at 8-bit and 4-bit. The repo records where the faster path had correctness and concurrency limits, not only the speed.

github.com/Weschera/qwen38-27b-mlx-mtp-recipe (opens in a new tab)↗
GitHub · Mac

DeepSeek vision on a Mac Studio

A native Mac Studio deployment of a DeepSeek vision model, with the artifact and the repair record. The repo separates how much context was configured from how the model behaved when that context was filled.

github.com/Weschera/DeepSeek-V4-Flash-Vision-Exp-ds4-Mac-Studio (opens in a new tab)↗

More public serving recipes, including the other Mac and DGX write-ups, are indexed at wesche.com/lab/research. Those blurbs are the repositories' own summaries.
